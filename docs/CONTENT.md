## Harvesting source reconciliation, 27 October 2026

The joint Consolidation Paper, sections 2.3–2.4 and 3.1, was compared with the supplied `cam.py`, `crop_resize.py`, `box_utils.py`, `color_detection.py`, `fps_utils.py` and Arduino receiver code. The paper supports 2,445 self-collected images with AI-assisted annotation and an adapted pre-trained YOLOv8n model. The owner supplies the responsibility allocation; the presence of a training tutorial is not evidence that Anton trained the final custom model.

- The paper specifies removing the upper 45% and resizing to 256 × 96 pixels. The supplied crop script removes the upper third; its included parameters calculate 384 × 160 pixels. The main narrative therefore explains cropping and resizing without treating either as a verified final configuration.
- Approximately 15 position updates per second is a reported paper result. The FPS utility calculates processing speed but supplies no independent final measurement log; no new rate is claimed on the page.
- The supplied runtime script loads `yolov8n.pt`; that filename does not establish which custom weights were used in the final experimental comparison. The training notebook is a generic tutorial using another dataset and YOLOv8s training, not the final harvesting training configuration. Roboflow as the project’s training service remains an unconfirmed recollection and is omitted from the narrative.
- Confidence is extracted internally but not transmitted. The supplied serial writer sends image width, height, centre X, centre Y and colour; the receiver parses those fields. The available Arduino code contains test/simulation settings and commented approach-stop logic, so it does not independently prove the final deployed stop configuration.
- Timing ended at the start of the grasp sequence. Existing values and failure counts are unchanged; task failures include collection outcomes even though grasping time was excluded from the time measurement.
